🌐 Why NoSQL?

RDBMS is excellent at consistency and complex relationships — but scaling it horizontally across many machines is hard.
  • Horizontal scaling: add more machines instead of a bigger one
  • Flexible / schema-less data — structure can vary row to row
  • High write throughput at massive scale
  • Natural fit for semi-structured or unstructured data

🗃️ Four Types of NoSQL Databases

TypeExampleBest For
Key-ValueRedis, DynamoDBSimplest — O(1) lookup by key
DocumentMongoDB, CouchDBJSON-like, flexible fields
Column-familyCassandra, HBaseWrite-heavy, wide-column workloads
GraphNeo4jRelationship-heavy data — social networks

⚖️ CAP Theorem

During a network partition, a distributed system can only guarantee 2 of these 3:

Consistency

Every read gets the latest write

Availability

Every request gets a response

Partition Tolerance

System keeps working despite network splits

Most real distributed NoSQL systems choose AP (available + partition-tolerant, eventual consistency) over strict consistency.

🆚 SQL vs NoSQL — ACID vs BASE

ACID (RDBMS)BASE (typical NoSQL)
PhilosophyStrict correctnessBasically Available, Soft state, Eventual consistency
Best forBanking, the College DBSocial feeds, IoT streams, catalogs
Trade-offConsistency over raw scaleScale/speed over strict correctness
