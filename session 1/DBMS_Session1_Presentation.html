📁 File System vs DBMS

Why did we move from files to databases?

Real-World Scenario: A college maintains student data in Excel/CSV files across multiple departments.
IssueFile System ProblemDBMS Solution
🔴 Data RedundancySame address stored in 5 different filesNormalization - store once, reference via ID
🔴 InconsistencyUpdate one file, others remain oldSingle source of truth
🔴 Data IsolationData scattered across filesCentralized storage with relationships
🔴 AtomicityTransfer fails → partial updateTransactions (all or nothing)
🔴 Concurrent AccessTwo users overwrite each otherLocking & Concurrency Control
🔴 SecurityFile access = see everythingRole-based access control
🔴 IntegrityNegative marks can be enteredConstraints (CHECK, NOT NULL)

🗄️ What is a Database & DBMS?

Database

An organized collection of logically related data stored together to serve multiple applications efficiently.

DBMS

Software that enables users to create, maintain, and control access to databases. Acts as an interface between users and data.

Popular DBMS Examples

TypeExamplesUse Case
Relational (RDBMS)MySQL, PostgreSQL, Oracle, SQL ServerBanking, E-commerce, ERP

🔺 Three-Level Schema Architecture

ANSI-SPARC Architecture - Provides Data Independence

┌─────────────────────────────────────────┐ │ EXTERNAL LEVEL (View Level) │ │ ┌─────────────┐ ┌─────────────┐ │ │ │ User A │ │ User B │ │ │ │ (Student │ │ (Faculty │ │ │ │ view) │ │ view) │ │ │ └─────────────┘ └─────────────┘ │ ├─────────────────────────────────────────┤ │ CONCEPTUAL LEVEL (Logical) │ │ Tables, Constraints, Relationships │ │ "WHAT data is stored" │ ├─────────────────────────────────────────┤ │ INTERNAL LEVEL (Physical) │ │ B-trees, Hashing, Storage blocks │ │ "HOW data is stored" │ └─────────────────────────────────────────┘

Logical Data Independence

Change conceptual schema without affecting external schemas

Ex: Add column → Apps still work

Physical Data Independence

Change internal schema without affecting conceptual schema

Ex: Change index type → Tables unchanged

📐 Relational Model Introduction

Proposed by E.F. Codd (IBM, 1970) - Father of Relational Databases

Core Idea: Data is organized as a collection of relations (tables)

Key Terminology

TermMeaningExample
RelationTableStudents table
TupleRow / RecordOne student's data
AttributeColumn / FieldName, Roll_No, Marks
DomainSet of valid valuesMarks: 0-100
DegreeNumber of columns5 attributes = degree 5
CardinalityNumber of rows100 students = cardinality 100
SchemaStructure of relationStudent(Roll_No, Name, Dept)
InstanceActual data at a point in timeCurrent set of rows
Properties of Relations:
1. No duplicate tuples   2. Tuples are unordered   3. Attributes are atomic
4. Unique attribute names   5. Values from same domain

🔧 Hands-On: MySQL Setup & First Database

15 Minutes Practical Lab

Step 1: Install MySQL

# Windows: Download from dev.mysql.com/downloads/installer/ # Linux: sudo apt update sudo apt install mysql-server # Mac: brew install mysql brew services start mysql

Step 2: Create Database & Table

-- Login to MySQL mysql -u root -p -- Create Database CREATE DATABASE college_db; -- Use the database USE college_db; -- Create table with constraints CREATE TABLE students ( roll_no INT PRIMARY KEY, name VARCHAR(50) NOT NULL, department VARCHAR(30), marks DECIMAL(5,2) CHECK (marks >= 0 AND marks <= 100), email VARCHAR(50) UNIQUE ); -- Insert data INSERT INTO students VALUES (1, 'Rahul Sharma', 'EC', 85.5, 'rahul@college.edu'), (2, 'Priya Patel', 'EC', 92.0, 'priya@college.edu'), (3, 'Amit Kumar', 'EC', 78.5, 'amit@college.edu'); -- View data SELECT * FROM students;
