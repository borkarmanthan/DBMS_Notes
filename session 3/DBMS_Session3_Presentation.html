🧮 What is Relational Algebra?

Relational Algebra is a procedural query language that takes one or more relations as input and produces a new relation as output. It is the theoretical foundation of SQL.

Why Study RA?

  • Every SQL query has an equivalent RA expression
  • Understanding RA helps you write better SQL
  • Standard topic in GATE & placements
  • Query optimizers use RA internally

Key Property

Closure Property:
The result of ANY operation is always another relation.

Input: Relation(s) → Output: Relation
This allows chaining operations!

🔍 Select (σ) — Horizontal Subset

Select (σ) filters rows (tuples) that satisfy a condition. It keeps ALL columns but removes rows that don't match.
σ <condition> (Relation)

Examples

Example 1: Simple Condition

σ dept = 'EC' (Student)

"Select all students from EC department"

Example 2: Numeric Comparison

σ marks > 80 (Student)

"Select students with marks greater than 80"

Example 3: Multiple Conditions (AND)

σ dept='EC' ∧ gender='F' ∧ marks>75 (Student)

"EC female students with marks > 75"

Example 4: OR Condition

σ dept='EC' ∨ dept='CS' (Student)

"Students from EC OR CS department"

-- SQL Equivalent of Example 3 SELECT * FROM student WHERE dept = 'EC' AND gender = 'F' AND marks > 75;

📋 Project (π) — Vertical Subset

Project (π) selects specific columns (attributes), removing duplicates. It keeps selected columns and all matching rows.
π <attribute_list> (Relation)

Examples

Example 1: Single Column

π name (Student)

"Get names of all students"

⚠️ Removes duplicates! In SQL: SELECT DISTINCT

Example 2: Multiple Columns

π name, dept (Student)

"Get names and departments"

🎯 Combined: Select THEN Project

π name (σ dept='EC' (Student))

"Names of EC students"

❌ Wrong order: σ dept='EC' (π name (Student))
→ ERROR! dept was projected away!
-- SQL Equivalent of Combined Example SELECT DISTINCT name FROM student WHERE dept = 'EC';

🔄 Set Operations

⚠️ Union Compatibility Required: Two relations must have the same number of attributes (degree) and corresponding attributes from the same domain.

Union (∪)

All tuples in R OR S (duplicates removed)

π roll_no (Sports) ∪ π roll_no (Cultural)

"Students in Sports OR Cultural club"

✅ Commutative: R ∪ S = S ∪ R

Difference (−)

Tuples in R but NOT in S

π roll_no (Sports) − π roll_no (Cultural)

"Students in Sports but NOT Cultural"

❌ NOT Commutative: R − S ≠ S − R

Intersection (∩)

Tuples in R AND S (both)

π roll_no (Sports) ∩ π roll_no (Cultural)

"Students in BOTH clubs"

💡 Derived: R ∩ S = R − (R − S)

┌─────────┐ ┌─────────┐ │ R │ │ S │ │ ┌───┐ │ │ ┌───┐ │ │ │ ∪ │ │ │ │ ∩ │ │ │ └───┘ │ │ └───┘ │ └─────────┘ └─────────┘ All in either Only in both

✖️ Cartesian Product (×)

Cartesian Product combines EVERY tuple from R with EVERY tuple from S. If R has m rows and S has n rows, R × S has m × n rows.
R × S

Example

Student (100 rows) × Department (5 rows)

= 500 rows!

Most combinations are meaningless (student paired with wrong dept)

✅ Real Usage: × + σ = Join

σ s.dept_id = d.dept_id (Student × Department)

Filter only valid combinations → meaningful result!

-- SQL: Cross Join (rarely used alone) SELECT * FROM student CROSS JOIN department; -- SQL: Cross Join + WHERE = Inner Join SELECT * FROM student s, department d WHERE s.dept_id = d.dept_id;

🔗 Joins

Join combines tuples from two relations based on a related column. It is the most common operation in databases.

Join = Cartesian Product + Select

🔗 Natural Join vs Equi Join

Natural Join (⋈)

  • Automatically joins on common attributes
  • Removes duplicate columns
  • Requires same attribute names
Student ⋈ Department

Joins on dept_id, keeps one dept_id column

Equi Join

  • Joins on equality condition
  • Keeps both columns
  • More explicit and flexible
σ s.dept_id = d.dept_id (Student × Department)

Keeps both dept_id columns (Student.dept_id, Department.dept_id)

-- Natural Join SELECT * FROM student NATURAL JOIN department; -- Equi Join (explicit) SELECT * FROM student s JOIN department d ON s.dept_id = d.dept_id;

🌐 Outer Joins

Left Outer Join (⟕)

All tuples from LEFT + matching from right

Student ⟕ Department

"All students + their dept (NULL if no dept)"

Right Outer Join (⟖)

All tuples from RIGHT + matching from left

Student ⟖ Department

"All departments + their students (NULL if no students)"

Full Outer Join (⟗)

All tuples from BOTH sides

Student ⟗ Department

"All students AND all departments, NULLs where no match"

Visual Comparison

LEFT: [Student ◀═══▶ Dept] + Student only RIGHT: [Student ◀═══▶ Dept] + Dept only FULL: [Student ◀═══▶ Dept] + Student only + Dept only
-- Left Outer Join SELECT s.name, d.dept_name FROM student s LEFT JOIN department d ON s.dept_id = d.dept_id; -- Right Outer Join SELECT s.name, d.dept_name FROM student s RIGHT JOIN department d ON s.dept_id = d.dept_id;

EASY Q1. Find all students belonging to the EC department (dept_id = 1).
σ dept_id = 1 (Student)
SELECT * FROM student WHERE dept_id = 1;
EASY Q2. Find names and emails of all students.
π name, email (Student)
SELECT DISTINCT name, email FROM student;
EASY Q3. Find names of female students with CGPA > 8.5.
π name (σ gender='F' ∧ cgpa>8.5 (Student))
SELECT DISTINCT name FROM student WHERE gender = 'F' AND cgpa > 8.5;
EASY Q4. Find all distinct departments that have at least one student.
π dept_id (Student)
SELECT DISTINCT dept_id FROM student;
EASY Q5. Find students born after January 1, 2004.
σ dob > '2004-01-01' (Student)
SELECT * FROM student WHERE dob > '2004-01-01';

📝 Practice Problems 6-10 (Level: Medium)

Multi-table queries using Joins

MEDIUM Q6. Find names of students along with their department names.
π name, dept_name (Student ⋈ Department)
SELECT s.name, d.dept_name FROM student s JOIN department d ON s.dept_id = d.dept_id;
MEDIUM Q7. Find EC department students who have enrolled in any course.
π name (σ dept_id=1 (Student) ⋈ Enrollment)
SELECT DISTINCT s.name FROM student s JOIN enrollment e ON s.roll_no = e.roll_no WHERE s.dept_id = 1;
MEDIUM Q8. Find course names and names of students enrolled in them.
π course_name, name (Course ⋈ Enrollment ⋈ Student)
SELECT DISTINCT c.course_name, s.name FROM course c JOIN enrollment e ON c.course_id = e.course_id JOIN student s ON e.roll_no = s.roll_no;
MEDIUM Q9. Find students enrolled in course 'EC301'.
π name (σ course_code='EC301' (Course) ⋈ Enrollment ⋈ Student)
SELECT DISTINCT s.name FROM student s JOIN enrollment e ON s.roll_no = e.roll_no JOIN course c ON e.course_id = c.course_id WHERE c.course_code = 'EC301';
MEDIUM Q10. Find students who have NOT enrolled in any course.
π roll_no, name (Student) − π roll_no, name (Student ⋈ Enrollment)
SELECT roll_no, name FROM student EXCEPT SELECT s.roll_no, s.name FROM student s JOIN enrollment e ON s.roll_no = e.roll_no;
