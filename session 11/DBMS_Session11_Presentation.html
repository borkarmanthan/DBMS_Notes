Views Procedures Functions Triggers

🪟 Views

A view is a virtual table defined by a stored query — it doesn't store data itself, it re-runs its query each time you access it.
CREATE VIEW student_course_view AS SELECT s.roll_no, s.name, c.course_name, e.grade FROM student s JOIN enrollment e ON s.roll_no = e.roll_no JOIN course c ON e.course_id = c.course_id; SELECT * FROM student_course_view WHERE grade = 'A';
A view is updatable ONLY if it maps to a single base table with no aggregates, GROUP BY, DISTINCT, or subqueries in the SELECT list.

⚙️ Stored Procedures

A precompiled, named block of SQL that takes parameters and can be called repeatedly — keeps logic inside the database.
DELIMITER // CREATE PROCEDURE GetStudentCGPA(IN p_roll_no INT, OUT p_cgpa DECIMAL(3,2)) BEGIN SELECT cgpa INTO p_cgpa FROM student WHERE roll_no = p_roll_no; END // DELIMITER ; CALL GetStudentCGPA(101, @cgpa); SELECT @cgpa;
ParameterDirection
INValue passed into the procedure (default)
OUTValue passed back to the caller
INOUTBoth directions

⚡ Triggers

Code that fires AUTOMATICALLY on INSERT/UPDATE/DELETE — no explicit call needed.
TimingGood For
BEFOREValidation, modifying the incoming value
AFTERAudit logging, cascading side effects

NEW = row after the change (unavailable on DELETE). OLD = row before the change (unavailable on INSERT).

🔧 Hands-On: Audit Trigger

CREATE TABLE student_audit ( audit_id INT AUTO_INCREMENT PRIMARY KEY, roll_no INT, old_cgpa DECIMAL(3,2), new_cgpa DECIMAL(3,2), changed_at DATETIME DEFAULT CURRENT_TIMESTAMP ); DELIMITER // CREATE TRIGGER trg_cgpa_update BEFORE UPDATE ON student FOR EACH ROW BEGIN IF OLD.cgpa <> NEW.cgpa THEN INSERT INTO student_audit(roll_no, old_cgpa, new_cgpa) VALUES (OLD.roll_no, OLD.cgpa, NEW.cgpa); END IF; END // DELIMITER ; UPDATE student SET cgpa = 9.8 WHERE roll_no = 101; SELECT * FROM student_audit;
Updating the row and immediately querying the audit table to see the change logged is the payoff moment of this whole session.
