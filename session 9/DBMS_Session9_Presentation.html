⚙️ The Query Processing Pipeline

Parser → Query Translation → Optimizer → Execution Engine
StageWhat Happens
ParserChecks SQL syntax and semantics (do the tables/columns exist?)
TranslationConverts SQL into an internal relational algebra expression
OptimizerEstimates cost of multiple possible execution plans, picks the cheapest
Execution EngineActually runs the chosen plan and returns rows
Cost is dominated by disk I/O, almost always — fewer block reads wins, not fewer CPU comparisons.

🔗 Join Algorithms

AlgorithmHow It WorksBest When
Nested LoopFor each outer row, scan the inner tableOne side is tiny or indexed
Block Nested LoopReads in blocks/pages, not row-by-rowReduces disk I/O over plain nested loop
Sort-Merge JoinSort both sides, then mergeInputs already sorted, or sorted output needed
Hash JoinBuild a hash table on the smaller side, probe with the largerLarge, unsorted equi-joins

🎯 Optimization Techniques

Predicate Pushdown

Filter rows as early as possible, before joins — fewer rows to join means less work everywhere downstream.

Projection Pushdown

Select only the columns you need, as early as possible — never SELECT * out of habit.

Join Order

Put the most selective filter or smallest intermediate result first in the join sequence.

Use Indexes

Indexes on join and filter columns let the optimizer skip full scans entirely.

🔍 Reading EXPLAIN Output

The "type" Column — Best to Worst

system > const > eq_ref > ref > range > index > ALL
ALL means a full table scan — the thing you're almost always trying to avoid.

The "Extra" Column

ValueMeaning
Using index✅ Query satisfied entirely by the index — best case
Using whereNormal — a filter was applied
Using filesort⚠️ Had to sort results outside index order
Using temporary⚠️ A temp table was built mid-query

🔧 Hands-On: Diagnose a Slow Query

SELECT s.name, c.course_name, e.grade FROM enrollment e JOIN student s ON e.roll_no = s.roll_no JOIN course c ON e.course_id = c.course_id WHERE s.dept_id = 1 ORDER BY e.grade;

Step 1 — EXPLAIN it

Look for "Using filesort" — grade has no index that gives it sorted order.

Step 2 — Add an index

CREATE INDEX idx_enroll_grade ON enrollment(course_id, grade);

Step 3 — Re-run EXPLAIN

Compare rows scanned and check whether "Using filesort" disappears.
