🎯 CORE CONCEPTS TO EMPHASIZE
═══════════════════════════════════════════════════════

  1. ATTRIBUTE TYPES (use colored markers on whiteboard!)
     Simple (blue) → Composite (orange) → Multivalued (green) → Derived (purple)

  2. COMPOSITE vs MULTIVALUED (common confusion)
     Composite = divisible (name → first, last)
     Multivalued = multiple instances (phone → {num1, num2})
     A name is composite but NOT multivalued (one person has one name)

  3. CARDINALITY RATIOS
     1:1 → FK + UNIQUE on either side
     1:N → FK on 'many' side only
     M:N → Junction table ALWAYS

  4. WEAK ENTITY
     Cannot exist without owner
     Double rectangle, double diamond, double line
     Composite PK = (owner_PK, partial_key)

  5. MAPPING RULES (7 rules — students MUST memorize)
     Strong → Table | Composite → Flatten | Multivalued → Separate table
     1:1 → FK+UNIQUE | 1:N → FK on many | M:N → Junction | Weak → Composite PK

🔧 HANDS-ON: COLLEGE SYSTEM ER DIAGRAM
═══════════════════════════════════════════════════════

  Entities: Department, Student, Course, Faculty
  Attributes:
    - Student: roll_no (PK), name, dob, gender, cgpa, {phone} (multivalued)
    - Faculty: faculty_id (PK), first_name, last_name (composite), salary
    - Department: dept_id (PK), dept_name, location
    - Course: course_id (PK), course_code, course_name, credits

  Relationships:
    - Department has Student → 1:N
    - Department offers Course → 1:N
    - Student enrolls in Course → M:N
    - Faculty teaches Course → 1:N
    - Department has HOD Faculty → 1:1

  Mapping Result (same as Session 2 College DB!)
  → This connects ER model to their existing SQL knowledge

═══════════════════════════════════════════════════════
⚠️ COMMON STUDENT MISTAKES
═══════════════════════════════════════════════════════

  1. Confusing composite and multivalued attributes
  2. Forgetting M:N relationships need a junction table
  3. Putting FK on the wrong side of 1:N relationships
  4. Not marking weak entities with double rectangles
  5. Forgetting to include the owner's PK in weak entity's table
  6. Trying to store multivalued attributes as comma-separated strings

═══════════════════════════════════════════════════════
💡 TEACHING TIPS
═══════════════════════════════════════════════════════

  1. Use colored chalk/markers for different attribute types
  2. Draw the complete College System ER diagram on the board
  3. Show how it maps EXACTLY to the tables they created in Session 2
  4. Let students use draw.io in the last 10 minutes
  5. For weak entities, use the "child without parent" analogy
  6. Emphasize: "M:N ALWAYS means a junction table — no exceptions"
