🔗 What is a Functional Dependency?

X → Y (X functionally determines Y) means: for any two tuples with the same X value, they MUST have the same Y value.

Simple Analogy

If you know Roll Number ↓ You automatically know Name ↓ roll_no → name

Formal Definition

For all tuples t1, t2 in R:
If t1[X] = t2[X], then t1[Y] = t2[Y]

Types of FDs

TypeConditionExample
TrivialY ⊆ X(roll_no, name) → roll_no
Non-TrivialY ⊄ Xroll_no → name
Completely Non-TrivialX ∩ Y = ∅roll_no → name

📐 Armstrong's Axioms

Sound & Complete inference rules for deriving FDs

A1. Reflexivity

If Y ⊆ X, then X → Y

Ex: (A,B) → A, (A,B) → B

A2. Augmentation

If X → Y, then XZ → YZ

Ex: A→B implies AC→BC

A3. Transitivity

If X → Y and Y → Z, then X → Z

Ex: roll_no→dept, dept→hod ⇒ roll_no→hod

D1. Union

If X → Y and X → Z, then X → YZ

Ex: roll_no→name, roll_no→dept ⇒ roll_no→(name,dept)

D2. Decomposition

If X → YZ, then X → Y and X → Z

Ex: roll_no→(name,dept) ⇒ roll_no→name, roll_no→dept

D3. Pseudo-Transitivity

If X → Y and WY → Z, then WX → Z

Ex: A→B and BC→D ⇒ AC→D

🔍 Attribute Closure (X⁺)

X⁺ = All attributes that can be determined by X using the given FDs.

Algorithm: Compute X⁺

1. X⁺ = X
2. Repeat until no change:
   a. For each FD Y → Z in F:
      b. If Y ⊆ X⁺ and Z ⊄ X⁺:
         c. X⁺ = X⁺ ∪ Z
3. Return X⁺

Example

R(A,B,C,D,E), F = {AB→C, C→D, D→E}

Find (AB)⁺: Start: {A, B} AB→C: add C → {A,B,C} C→D: add D → {A,B,C,D} D→E: add E → {A,B,C,D,E} Result: (AB)⁺ = ALL AB is a super key!

Uses of Closure

  • Find candidate keys
  • Check if X → Y is implied
  • Find minimal cover
Finding Candidate Keys:
1. Attributes only on LHS → must be in key
2. Attributes only on RHS → never in key
3. Compute closures of combinations

✂️ Minimal Cover (Canonical Cover)

A minimal cover Fc is an equivalent set of FDs that is:
  1. Minimal (no extraneous attributes)
  2. Unique LHS for each FD
  3. No redundant FDs

Algorithm

Step 1: Decompose RHS (single attribute each)
Step 2: Remove extraneous attributes from LHS
Step 3: Remove redundant FDs

Example

F = {A→BC, B→C, A→B, AB→C}

Step 1: Decompose {A→B, A→C, B→C, A→B, AB→C} = {A→B, A→C, B→C, AB→C} Step 2: Check AB→C Is A extraneous? (B)⁺ = {B,C} C ∈ {B,C}? YES! Replace with B→C But B→C already exists. Remove AB→C. Step 3: Check A→C Remove it: (A)⁺ with {A→B, B→C} = {A,B,C}. C ∈ (A)⁺? YES! A→C is redundant. Fc = {A→B, B→C}

Verification

Can Fc derive all original FDs?

A→BC: A→B (given), A→C (A→B→C), union ✓
B→C: Given in Fc ✓
A→B: Given in Fc ✓
AB→C: B→C (given), augment ✓

🗂️ Schema Decomposition

Why Decompose?

Insertion Anomaly:
Can't insert dept without a student

Update Anomaly:
Change HOD → update all rows

Deletion Anomaly:
Delete last student → lose dept info

Good Decomposition

Lossless Join:
R1 ⋈ R2 = R (no data lost)

Test: R1 ∩ R2 → R1 OR R1 ∩ R2 → R2

Dependency Preserving:
All FDs checkable without joins
-- Before: Redundant, anomaly-prone STUDENT_DEPT(roll_no, name, dept_id, dept_name, hod) -- After: Clean decomposition STUDENT(roll_no, name, dept_id) -- roll_no → name, dept_id DEPARTMENT(dept_id, dept_name, hod) -- dept_id → dept_name, hod -- Check Lossless: R1 ∩ R2 = {dept_id} -- dept_id → R2? YES! (dept_id is PK of DEPARTMENT)
